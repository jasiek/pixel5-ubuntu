# SM7250 mainline tree for redfin: a reproducible recipe for P6.1

Research date: 2026-11-19. Scope: PLAN step P6.1 ("assemble a mainline tree that builds a generic SM7250 kernel"), sized for the **first gate** only: boot to our initramfs with USB2 gadget networking and UFS (P6.2 / P6.4 first bullet). Builds on `docs/research/mainline.md` and does not repeat it.

Method: GitHub API, `git ls-remote`, the patchwork API and lore mboxes (lore served `t.mbox.gz` today without Anubis trouble). I shallow-fetched the bases into the scratchpad, applied each candidate series with `git am`, and built two candidate trees in the `pixel5-build` arm64 image (clang, `LLVM=1`, arm64 `defconfig` + a minimal fragment + a stub DTS). I did not touch the phone.

## TL;DR

- **First gate: start from linux-next `next-20261021` + 23 patches taken unchanged from `effeffe/nairoArchLinuxArmTools` @ `665f098`.** All 23 apply with `git am` [verified]. The tree builds Image + a stub SM7250 DTB with no warnings [verified]. Every source can be a pinned submodule, and our repo carries no third-party patch files.
- **The forward path is also checked:** `v7.4-rc3` + Sreeshankar K **v15** (8) + nairo's driver patches. Every driver patch applies unchanged [verified]. Only the four nairo DT-node patches (TLMM, SMMU, USB, UFS) need fuzz against the v15 dtsi [verified]. That tree builds too [verified]. Switch when v15 lands, or once the first gate is passed.
- **Top risks:**
  1. nairo's repo is **AGPL-3.0**, and 104/159 of its patches (including 18 of our 23) have **no Signed-off-by**. Licence intent for the kernel patches needs the author's confirmation.
  2. The **redfin ABL / DTB path is untested**, and it is the real first gate (P6.2).
  3. The **case-insensitive macOS scratch volume** corrupts a kernel checkout. Builds must export the tree into the container or onto the case-sensitive volume.

### 2.3 Build check (scratchpad, not kept)

Setup: arm64 `defconfig` plus this fragment: `SM_GCC_7250=y PINCTRL_SM7250=y PHY_QCOM_QMP_UFS=y SCSI_UFS_QCOM=y PHY_QCOM_USB_SNPS_FEMTO_V2=y USB_DWC3_QCOM=y USB_CONFIGFS_NCM=y USB_CONFIGFS_ACM=y PSTORE_RAM=y PSTORE_CONSOLE=y PSTORE_PMSG=y ARM_QCOM_CPUFREQ_HW=y`. The stub DTS includes `sm7250.dtsi` and enables `ufs_mem_hc`, `ufs_mem_phy`, `usb_1_hsphy` and `usb_1` (peripheral, high-speed). Every fragment line survived `olddefconfig`.

- Option A (`next-20261021` + 24 patches, including 0112): `make Image qcom/sm7250-test.dtb` passed, with 0 compiler warnings. Image is 42,748,416 bytes, well inside the 96 MiB `boot` partition. About 7 min on 10 cores [verified].
- Option C (`v7.4-rc3` + v15 + icc v6 + nairo driver patches + fuzzed 0021–0024): `make Image qcom/sm7250-test.dtb` passed, with 0 compiler warnings. Image is 42,834,432 bytes and the stub DTB 16.8 KB. `INTERCONNECT_QCOM_SM7250=y` came in by default [verified].

## 4. Vendoring under this repo's rules

Proposed `.gitmodules` additions. Licences were checked above. The kernel is GPL-2.0. **nairo is AGPL-3.0**: confirm with the owner and the author before adding it (see risks).

```ini
[submodule "external/linux-next"]
	path = external/linux-next
	url = https://git.kernel.org/pub/scm/linux/kernel/git/next/linux-next.git
	shallow = true          # pin 9a482184d910775cf648863148944945b74e2815 (next-20261021)
	ignore = dirty
[submodule "external/nairo"]
	path = external/nairo
	url = https://github.com/effeffe/nairoArchLinuxArmTools
	shallow = true          # pin 665f098e299ec2f8f155a8ac63e40d951d89468f
# later, for the panel path (GPL-2.0):
# external/avicii-mainline  https://github.com/lazybrar/avicii-mainline  @ 71944476a139…
```

kernel.org serves `git fetch --depth 1 <url> <sha>` for both pins [verified], so shallow submodule init works. When moving to Option C, re-pin the same path to `v7.4-rc3` (`aebb7274476403040d582c61478df8f4a7bf9cd3`) or to a later tag. lore series are not git remotes. Two ways to carry them:
1. Commit the `b4 am` output (`kernel/mainline/upstream/*.mbx`, unmodified, with Message-IDs) as third-party patches under their GPL-2.0 SoB.
2. Fetch them at build time by Message-ID with a checksum.

Option 1 conflicts with the letter of "third-party only as submodules", so **the owner must decide**. Option A avoids the question for now.

Layout:

```
kernel/mainline/
  series              # one line per patch: "<source> <path>", sources: nairo | local (| upstream later)
  redfin.config       # fragment over arm64 defconfig (SPDX: MIT, like redfin-ubuntu.config)
  patches/NNNN-*.patch   # ours, GPL-2.0-only (first: the redfin board DTS, P6.3)
scripts/build-mainline.sh
```

`scripts/build-mainline.sh` follows the same shape as `build-kernel.sh`: re-exec through `dev.sh` with `DEV_CROSS=1`, use `LLVM=1` and ccache. Two differences:

1. **Never patch the submodule work tree.** `git -C external/linux-next worktree add --detach build/mainline/src <pin>`. Apply the `series` entries in order with `git am --3way` (set `GIT_COMMITTER_NAME/EMAIL`; `safe.directory='*'`). Write a stamp of `sha256(pin + series + every patch file)`, and rebuild the worktree only when the stamp changes. `git log` in `build/mainline/src` then shows one commit per patch, so failures bisect.
2. **Config:** `make defconfig`, then `merge_config.sh -m` with `kernel/mainline/redfin.config` (run inside `$OUT`, which is the Pixel 2 lesson), then `olddefconfig`. Then the same "WARN not applied" loop as `build-kernel.sh`. Targets: `Image.gz` (or `Image`; see risk 6), `qcom/sm7250-google-redfin.dtb`, `modules`.

First-gate fragment: the §2.3 list, plus the systemd and initramfs basics from `kernel/redfin-ubuntu.config` that are not in arm64 defconfig. Everything boot-critical should be `=y`: GCC, TLMM, UFS, PHYs, dwc3, gadget, pstore. Add `CONFIG_QCOM_LMH=y` if cpufreq-hw is `=y`. Optional: trim other `ARCH_*` platforms later to shrink the Image.

## 5. Risks and unknowns

1. **nairo licence and provenance** [verified facts, open question]. The repo is AGPL-3.0. The kernel files in it declare GPL-2.0-only or BSD-3-Clause. 18 of our 23 patches lack Signed-off-by and are marked AI-generated and unreviewed. For private builds, a pinned submodule is fine. Before we ship images (P6.5/P7), ask effeffe (Filippo Falezza) to state GPL-2.0-only for `kernel/patches/`, or replace them with avicii (GPL-2.0) and our own rework.
2. **The boot path is untested on redfin** [unverified]. Nobody has a public, confirmed mainline boot on redfin; sohalartz claims one but shows no log. The gate depends on P6.2: DTB in `vendor_boot_b`, `msm-id <400 0x20000>,<440 0x20000>`, `board-id <0xb1e05 0>`, and dtbo handling. This recipe only gets as far as "it builds".
3. **Case-insensitive volumes break kernel checkouts** [verified]. A worktree in `/private/tmp` showed modified `include/uapi/linux/netfilter/xt_*.h` and `net/netfilter/xt_*.c` right after checkout. Keep `build/mainline/src` on the case-sensitive repo volume, as CLAUDE.md requires. I built from `git archive` inside the container.
4. **TZ-owned GPIOs** [partly verified]. The live DT TLMM node has `goog,ignored-gpios = <0 1 2 3>`, so redfin needs at least `gpio-reserved-ranges = <0 4>` (avicii and sohalartz agree). nairo reserves 59–62 on its board. Whether that range also applies to redfin is unverified. Touching a TZ GPIO hangs the bus.
5. **UFS on redfin** [unverified]. nairo's UFS fixes (32-bit DMA mask, permanent `qphy.lvl` vote, HS-G3 at 150 MHz) were tuned for nairo's UFS part. Redfin has UFS 2.1 (Micron, Samsung or SK Hynix by SKU). The UFS SMMU SID is still unknown, so the 32-bit mask stays.
6. **ABL kernel and Image format** [unverified]. The defconfig Image is 42.7 MB uncompressed. Whether redfin's ABL takes raw `Image`, `Image.gz` or `Image.lz4` with header v3 is P6.2 work. The downstream build uses `Image.lz4`.
7. **cpufreq-hw with LMh absent** [verified in review, untested here]. sashiko-bot on v15 8/8 flags partial cpufreq init and a leak if `QCOM_LMH` isn't ready. Our build has `QCOM_LMH=m` and v9 has no LMh nodes. Either leave cpufreq out of the first image, or make LMh built-in once on v15.
8. **v15 will keep changing** [verified trend]. Fifteen versions in three months, with a header and compatible rename between v9 and v15. Pin by Message-ID and expect a DTS touch-up when it merges (7.5 or 7.6 is a guess).
9. **Ishu Brar's series target different maintainer trees** (icc-next, qcom for-next, msm-next, iommu) [verified bases]. They have not been tested together on one base, except in avicii's 7.3 tree.
